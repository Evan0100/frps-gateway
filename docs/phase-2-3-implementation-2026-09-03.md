# Phase 2 / Phase 3 实施记录（2026-09-03）

## 已完成

- 新增 SQLite 数据层：用户授权、一次性令牌、受管 IP 和飞书 `messageID` 幂等回复。
- 已实现一次性授权令牌和确认页；当前用户入口改为 `/start` 动态卡片和手动提交公网 IP，旧自动授权指令不再暴露。
- 新增授权确认页和 `/healthz`；公网地址强制为 HTTPS。支持网关原生 TLS，或仅监听本机后由 Nginx/Caddy 终止 TLS。
- 真实 IP 只在 TCP 对端属于 `trustedProxyCIDRs` 时读取 `X-Forwarded-For`，并从右向左跳过可信代理。
- 同一 IP 可由多个用户分别授权；用户只能撤销自己的授权，只要仍有其他有效授权，frps 条目继续保留。
- gateway 强制默认 TTL 4h、最大 24h、每名员工最多 3 个不同的有效 IP；刷新已有 IP 不占名额，授权链接超限时不消费令牌。
- 密钥可从环境变量或受限文件加载；`bot.enabled=false` 可快速关闭飞书长连接。
- 员工不设置访问时段；共享 IP 到期时间取最大值，frps 管理员时段作为 IP 全局策略保留。
- 网关启动时将 SQLite 中的有效授权重新应用到 frps。
- 飞书处理改为固定工作协程与有界队列；群聊可强制 @机器人；按用户限制每分钟请求数；日志不再记录完整指令正文。
- 新增 `/start` 动态菜单卡片和 `card.action.trigger` 长连接回调；“我的授权”直接查询本人记录，“撤销授权”通过带确认的 IP 按钮执行，操作者身份不从按钮参数读取。
- frps 白名单 `POST/DELETE` 请求体限制为 16 KiB，只接受一个 JSON 值并拒绝未知字段。
- frps HTTP vhost 不再转发客户端自带的 `X-Forwarded-For`，由 frps 生成可信来源地址。
- `gorilla/websocket` 升级到 `v1.5.3`，`golang.org/x/crypto` 升级到 `v0.56.0`，并声明 `go1.26.6` 工具链。
- 访问记录落库：frps 访问记录新增 `(instance, seq)` 进程内唯一标识；gateway `ingest` 默认每 5 秒拉取最近记录并去重写入 SQLite。缺少标识的数据会被拒绝，轮询错误会记录，序号断档会告警；默认保留 30 天，每小时清理，`ingest.enabled=false` 可关闭。
- 启动对账已改为双向：补回有效 grant，并删除没有任何有效 grant 的 gateway 受管 IP；未知的管理员手工条目不处理。

## 上线前必须完成（外部环境）

1. 使用真实域名和受信任证书提供 HTTPS；如果使用反向代理，网关保持 `127.0.0.1` 监听，并精确配置代理 CIDR。

3. 在公司飞书租户限制应用可用范围，配置 `allowAllUsers=true`、`requireMentionInGroup=true`，并用真实员工账号验证私聊、群聊和重复消息。
4. 为 SQLite 文件配置权限、每日备份和恢复演练；数据库写入成功而 frps 暂时失败时，需要观察告警并重启/触发对账。
5. 使用 Go 1.26.6+ 构建并在发布流水线再次运行 `govulncheck ./...`；执行真实 frps + gateway + 飞书端到端测试。

## 已知边界

- 一次性链接属于“持有即授权”的能力链接。链接绑定飞书用户的授权记录，但未接入飞书 OAuth，因此用户转发链接后，实际打开者的 IP 会记在原飞书用户名下。当前通过短时、单次、明确提示和审计降低风险；高安全场景应在后续接入飞书 OAuth。
- UDP/XTCP 等无法稳定获得最终访问者源 IP 的路径仍不受该 IP 白名单完整保护，应关闭不需要的协议和端口。
- 当前启动对账保证数据库有效授权会写回 frps；尚未自动删除 frps 中来源不明的手工条目，以避免误删管理员紧急配置。
