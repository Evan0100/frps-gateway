## 1. 目标与范围

本计划采用"先可用、再强化、持续演进"的推进方式。第一优先级是让公司员工能通过飞书快速申请临时公网 IP 白名单;随后两天补齐自动识别 IP、持久化用户授权、限流、依赖升级和协议收敛。

- 复用已经完成的 frps 白名单、TTL、访问时段、持久化和管理 API。
- 飞书机器人面向全体内部员工提供自助申请,安全管理员保留全局管理权限。
- 所有授权默认临时有效,不提供普通员工永久加白。
- IP 白名单仅作为附加控制,不能替代 Web 服务补丁、MFA、WAF、终端防护和离线备份。

## 3. Phase 0:frps 白名单验证收口

白名单主体功能已经完成。本阶段不再扩展业务需求,只确认当前实现能够安全承接机器人调用。

### 3.1 已有能力

- IP 添加、延期、删除和查询。
- 默认 TTL、单条 TTL 和按星期/时段访问控制。
- 状态文件持久化与 frps 重启恢复。
- 管理页面、变更审计和访问决定记录。
- TCP、HTTP、HTTPS、TCPMux 以及 STCP/SUDP visitor 的既有入口校验。

### 3.2 上线前验证

- 先提交 frp 持久化改动，使用 Go 1.26.6 或更高安全版本重新构建、打包并部署；旧发布包不包含本次持久化修复。
- 在 Linux 环境验证空名单默认拒绝、加白放行、过期拒绝和删除后拒绝。
- 验证 frps 重启后只恢复未过期记录,状态文件损坏时安全失败。
- 确认 dashboard 仅监听 127.0.0.1,云安全组不开放管理端口。
- 确认 UDP、XTCP 和不需要的 KCP、QUIC、SSH Tunnel Gateway 暂不启用。
- 确认 frpc token 已轮换,frps 与全部合法 frpc 配置一致。

## 4. Phase 1:今天上线飞书员工自助申请

现有 frps-gateway 已具备飞书长连接、指令解析和 frps API 客户端。今天的重点是把"管理员机器人原型"调整为"内部员工自助服务",并完成真实环境联调。

### 4.1 首版用户指令

| 指令 | 行为 | 权限 |
|---|---|---|
| /start / 开始 / 菜单 | 打开动态操作卡片 | 内部员工 |
| 申请授权 1.2.3.4 4h | 按指定有效期申请授权 | 内部员工,受最大 TTL 限制 |
| 撤销授权 1.2.3.4 | 撤销本人对该 IP 的授权 | 授权所有者 |
| 我的授权 | 查询本人有效授权 | 内部员工 |

### 4.2 首版权限与限制

- 通过飞书事件中的 open_id 识别用户,不接受消息正文声明的身份。
- 普通员工只能管理本人授权；安全管理员通过仅本机可达的 frps 管理页面执行全局查询和紧急撤销。
- 默认有效期建议 4 小时,普通员工最大 24 小时。
- gateway 在 SQLite 事务中强制每名员工最多保留 3 个不同的有效 IP；刷新已有 IP 不占新名额。每分钟操作次数由 `requestsPerMinute` 强制。
- MessageID 必须去重,同一条消息只能执行一次。
- 首版不提供永久加白,不允许员工直接设置访问时段或批量导入。

### 4.3 首版最小安全底线

| 控制项 | 最低要求 | 验收方式 |
|---|---|---|
| 员工身份 | 仅受理内部租户用户;个人 open_id 可追溯 | 非内部用户请求被拒绝 |
| 幂等 | 按 MessageID 去重 | 重复投递不刷新 TTL |
| 调用链 | gateway 仅调用 127.0.0.1:7500 | 7500 不对公网开放 |
| 授权时长 | 默认 4h,最大 24h | 超限请求返回明确提示 |
| 操作留痕 | 记录用户、消息、IP、时间和结果 | 可按 MessageID 检索 |
| 并发控制 | 有界队列或固定工作线程 | 消息洪泛不会无限创建任务 |

### 4.4 上线方式

1. 先让 5 至 10 名员工试运行,覆盖公司网络、家庭宽带、移动热点和出差网络。
2. 观察加白成功率、错误原因、TTL 到期和同一公网 IP 共享情况。
3. 试运行通过后开放全员,同时保留人工管理页面作为故障恢复入口。
4. 公布使用说明:必须提交访问业务时所用网络的公网 IP,切换网络后需要重新申请。

## 5. Phase 2:明天实现自动检测公网 IP

| 重要限制 | 飞书消息事件的网络来源是飞书服务器,机器人无法从消息本身获取员工公网 IP。自动检测必须让员工使用目标电脑和目标网络打开一次性 HTTPS 链接。 |
|---|---|

### 5.1 推荐流程

1. 员工发送 `/start`，通过卡片进入访问申请流程。
2. 机器人生成绑定 open_id 和 MessageID 的一次性链接。
3. 员工用实际访问内网服务的设备和网络打开链接。
4. gateway 从连接来源识别公网 IP,并显示 IP、有效期和确认按钮。
5. 员工确认后,gateway 写入授权记录并调用 frps 管理 API。
6. 链接成功使用后立即失效,机器人回复最终结果。

### 5.2 一次性链接要求

- 随机且不可预测,5 分钟过期,只能成功使用一次。
- 绑定飞书 open_id、MessageID、预期操作和 TTL。
- 全程 HTTPS,不在 URL 中放置明文用户信息。
- 不直接信任外部 X-Forwarded-For;仅信任明确配置的前置代理。
- 成功、过期、重复使用和来源异常均写入审计。
- 生产部署由 Nginx/Caddy 在 443 终结 TLS 并自动续期证书，gateway 只监听 127.0.0.1:8080；云安全组不开放 8080 和 frps 管理端口。

## 6. Phase 2:SQLite 用户授权与对账

SQLite 保存"谁申请了什么",frps 保存"当前哪些 IP 生效"。两者职责不同,gateway 必须以用户授权记录为事实来源,并定期与 frps 对账。

### 6.1 建议数据字段

| 字段 | 用途 |
|---|---|
| grant_id | 授权记录唯一标识 |
| feishu_open_id / name | 申请人身份与展示名称 |
| message_id | 幂等去重与事件追溯 |
| ip | 标准化后的公网 IP |
| created_at / expire_at | 授权开始与到期时间 |
| revoked_at | 主动撤销时间 |
| status / result | 执行状态和 frps 调用结果 |
| source | explicit_ip 或 detection_link |

### 6.2 同一 IP 多人共享

同一公网 IP 可能属于公司出口、酒店、运营商 NAT 或多人家庭网络。员工撤销本人授权时,不能直接删除 frps 中的 IP。

首版员工授权只设置 TTL，不允许设置访问时段；同一 IP 的有效期取所有有效 grant 的最大值。管理员在 frps 页面配置的时段属于该 IP 的全局策略，gateway 刷新 TTL 时省略 `windows` 并保留该策略。

- 先在 SQLite 中撤销该员工的 grant。
- 查询同一 IP 是否仍存在其他未过期授权。
- 仍有有效授权时,按最晚到期时间刷新 frps 条目。
- 没有任何有效授权时,才从 frps 删除该 IP。
- gateway 启动后执行一次全量对账,之后定时增量校准。

## 7. Phase 3:后天完成关键安全加固

### 7.1 依赖与构建

- 版本以 `govulncheck` 和官方安全公告实测为准；当前最低采用 Go 1.26.6、gorilla/websocket 1.5.3、x/crypto 0.56.0。
- 重新运行 go test、go vet、govulncheck,并使用新工具链构建发布包。

### 7.2 frps 与管理 API

- frps 强制 TLS;token 通过权限受限文件加载,并定期轮换。
- 配置最小 allowPorts,关闭不使用的协议和入口。
- dashboard 仅监听回环地址,关闭 pprof,状态文件和配置限制 ACL。
- 白名单写接口请求体限制为 16 KiB,拒绝未知 JSON 字段和多余 JSON 值。
- 丢弃外部传入的 X-Forwarded-For,再由受控入口重新生成。
- 管理接口增加限流、失败登录记录和失败变更审计。

### 7.3 飞书机器人

- 采用个人身份授权;群聊必须显式 @机器人,管理员权限不由群成员身份自动获得。
- 使用有界队列和固定工作线程,增加用户级与全局限流。
- 建立 MessageID 唯一约束和可靠重试策略。
- 禁止在群聊中输出全公司白名单或其他员工身份信息。
- 异常加白、高频失败、长 TTL 和敏感服务访问触发告警。
- AppSecret、Basic Auth 密码、Encrypt Key 和 Verification Token 从环境变量或权限受限文件加载，不进入仓库，并纳入轮换流程。
- `bot.enabled=false` 可紧急关闭飞书长连接；如需停用全部授权，同时关闭反向代理授权路由或停止 gateway。

### 7.4 共享 IP 与第二道认证

- 员工 grant 只携带 TTL，不携带访问时段；共享 IP 按全部有效 grant 的最晚到期时间聚合。
- frps 管理员配置的访问时段是 IP 全局策略，gateway 刷新时省略 `windows`，不会覆盖该策略。
- 对外 HTTP 服务逐个配置 `httpUser/httpPassword`，与 IP 白名单独立；敏感服务优先使用 VPN、零信任和 MFA。

## 8. Phase 4:按服务细粒度授权

当前 frps 使用全局白名单,一个 IP 被允许后可能访问全部映射服务。后续应把授权模型升级为"员工 + 设备/IP + 服务/代理 + 有效期"。

| 用户 | 来源 IP | 目标服务 | 有效期 | 审批 |
|---|---|---|---|---|
| 普通员工 | 1.2.3.4 | ERP Web | 4 小时 | 自动 |
| 测试人员 | 5.6.7.8 | 测试环境 | 8 小时 | 自动或负责人 |
| 运维人员 | 9.10.11.12 | SSH/RDP | 1 小时 | 安全管理员 |
| 数据库管理员 | 13.14.15.16 | 数据库 | 1 小时 | 双人确认 |

普通 Web 服务可以短期自助授权;SSH、RDP、数据库、容器 API 和管理后台应采用更短有效期、显式审批和更强身份认证。

## 9. 角色与权限模型

| 角色 | 允许操作 | 禁止操作 |
|---|---|---|
| 内部员工 | 申请短期 IP、查看本人记录、撤销本人授权 | 查看全员名单、永久授权、访问敏感服务 |
| 业务负责人 | 审批所属服务的例外申请 | 跨业务审批、修改系统策略 |
| 安全管理员 | 全局查询、撤销、封禁、策略调整 | 绕过审计直接修改状态文件 |
| 系统运维 | 部署、备份、恢复和健康检查 | 冒用员工身份发起业务授权 |

## 10. 风险与应对

| 风险 | 影响 | 近期应对 | 长期措施 |
|---|---|---|---|
| 提交了错误网络的 IP | 员工仍无法访问 | 提示使用同一设备和网络 | 一次性检测链接 |
| 共享 NAT | 同一 IP 对多人有效 | 短 TTL、记录所有申请人 | 设备身份和零信任接入 |
| 飞书账号失陷 | 攻击者可申请访问 | 短 TTL、限流、异常告警 | MFA、设备校验、审批 |
| Web 服务自身漏洞 | 可能远程执行或勒索 | 补丁、WAF、最小权限 | 安全开发和持续扫描 |
| gateway 故障 | 无法新增授权 | 保留本机管理页面 | 高可用和对账恢复 |
| 审计被篡改 | 无法可靠追责 | 限制 ACL、远端日志 | 不可变审计存储 |

## 11. 验收标准

### 11.1 Phase 1 可用性验收

- 内部员工能通过明确 IP 指令在 10 秒内收到成功或可理解的失败回复。
- 非内部用户、超长 TTL、非法 IP、重复消息和超频请求均被拒绝或幂等处理。
- 名单到期后新连接自动拒绝,gateway 停止不影响 frps 现有转发。
- 每次操作均能关联到 open_id、MessageID、IP、时间和结果。

### 11.2 Phase 2 安全验收

- 一次性链接 5 分钟过期、单次使用且只能完成绑定用户的预期操作。
- 同一 IP 多人授权的新增、撤销和到期逻辑正确。
- gateway 重启后能够从 SQLite 恢复并与 frps 自动对账。
- 依赖漏洞扫描不再包含本计划列出的已修复版本问题。

### 11.3 发布验收

- 完成 Linux 环境 TCP/HTTP/HTTPS 端到端测试。
- 云安全组、主机防火墙和 allowPorts 与实际服务清单一致。
- 无 dashboard、数据库、RDP、SMB 或容器 API 的意外公网入口。
- 离线或不可变备份已完成一次恢复演练。
- 已备份旧二进制、frps 状态文件、SQLite（含 WAL）和配置，并按 `deployment-runbook.md` 完成一次回滚演练。
