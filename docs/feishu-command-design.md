# 飞书机器人指令与卡片交互设计

> 状态：Draft（设计方案，尚未全部实现）  
> 更新日期：2026-09-03

## 1. 设计目标

- 普通员工只需要记住 `/start`，主要操作通过飞书动态卡片完成。
- 对外统一使用“授权”概念，不向用户暴露“加白”“删白”“TTL”等运维术语。
- 当前支持全局 IP 授权，未来增加按服务授权时不更换主入口和核心动作名称。
- 用户身份只能来自飞书事件或卡片回调的 `open_id`，不能从消息正文或按钮参数指定。
- 普通员工只能查看和撤销自己的授权。

## 2. 统一术语

| 术语 | 含义 |
|---|---|
| 授权 | 允许指定公网 IP 在有限时间内访问公司服务 |
| 服务 | 一个明确的业务系统或 frp 代理，例如 ERP、文件服务或测试环境 |
| 有效期 | 授权自动失效前的持续时间 |
| 我的授权 | 当前飞书用户仍然有效的授权记录 |

机器人对员工展示“临时网络访问授权”，后台和运维文档仍可使用“frps IP 白名单”。

## 3. 当前阶段：全局 IP 授权

当前 frps 使用全局白名单。同一个 IP 被授权后，可能访问所有使用该白名单的映射服务，因此界面必须明确显示：

```text
当前授权范围：全部现有内网服务
```

### 3.1 对外指令

| 指令 | 行为 |
|---|---|
| `/start` | 打开“临时网络访问授权”主菜单 |
| `开始` | `/start` 的中文入口 |
| `菜单` | `/start` 的中文入口 |
| `申请授权 <IP> [有效期]` | 为指定公网 IP 申请临时授权 |
| `我的授权` | 查看本人全部有效授权 |
| `撤销授权 <IP>` | 撤销本人对指定 IP 的授权 |

示例：

```text
申请授权 118.25.93.30
申请授权 118.25.93.30 4h
申请授权 118.25.93.30 1d
我的授权
撤销授权 118.25.93.30
```

不再接受旧的加白、删白、白名单、help 及英文命令；无法识别的输入统一提示用户发送 `/start`。

### 3.2 主菜单卡片

```text
临时网络访问授权

当前授权范围：全部现有内网服务

点击「打开授权页面」即可自动授权你当前的公网 IP；链接 5m 内有效且仅可使用一次，过期后请重新发送 /start。

[打开授权页面]（跳转一次性授权链接）
[我的授权]
[撤销授权]
```

- “打开授权页面”：`/start` 和“返回菜单”时签发的一次性 HTTPS 授权链接（有效期 `linkTTL`，默认 5 分钟）；确认页自动识别公网 IP。链接签发失败时回退为“申请授权”按钮，显示手动填写公网 IP 和有效期的格式。
- “我的授权”：直接查询当前用户的有效记录，不要求再次发送文字指令。
- “撤销授权”：列出当前用户的有效 IP，每条记录提供带二次确认的撤销按钮。

### 3.3 回复文案

授权成功：

```text
授权成功

公网 IP：118.25.93.30
授权范围：全部现有内网服务
有效期：4 小时
到期时间：09-03 23:30
```

撤销成功：

```text
授权已撤销

公网 IP：118.25.93.30
```

无法识别输入：

```text
无法识别该操作，请发送 /start 打开菜单。
```

## 4. 未来阶段：按服务授权

按服务授权上线后，不增加 `申请ERP`、`申请文件服务` 等独立指令，而是在统一授权动作中增加“服务”参数。

### 4.1 指令扩展

| 指令 | 行为 |
|---|---|
| `申请授权 <服务代码> <IP> [有效期]` | 申请指定服务的临时授权 |
| `我的授权` | 查看本人所有服务的有效授权 |
| `我的授权 <服务代码>` | 只查看指定服务的有效授权 |
| `撤销授权 <服务代码> <IP>` | 撤销指定服务和 IP 的授权 |

示例：

```text
申请授权 ERP 118.25.93.30 4h
申请授权 TEST 118.25.93.30 1d
我的授权 ERP
撤销授权 ERP 118.25.93.30
```

### 4.2 卡片流程

```text
/start
  → 申请授权
  → 选择服务
  → 填写或自动识别公网 IP
  → 选择有效期
  → 确认授权范围
  → 完成
```

卡片展示服务中文名称；文字指令使用固定服务代码，避免重名、改名和输入差异。

### 4.3 服务目录

| 服务代码 | 显示名称 | frp 代理示例 | 默认有效期 | 是否敏感 |
|---|---|---|---|---|
| `ERP` | ERP 系统 | `erp-web` | 4h | 否 |
| `FILE` | 文件服务 | `file-server` | 4h | 否 |
| `TEST` | 测试环境 | `test-web` | 8h | 否 |
| `RDP` | 远程桌面 | `office-rdp` | 1h | 是 |

服务代码由后台配置维护，不允许用户通过按钮提交未登记的服务代码。敏感服务应采用更短有效期，并结合独立账号、MFA、VPN 或零信任控制，不能只依赖 IP 白名单。

## 5. 数据与权限模型

当前授权记录：

```text
用户 + IP + 有效期
```

未来授权记录：

```text
用户 + 服务ID + IP + 有效期
```

共享出口 IP 的有效期聚合维度必须从 `IP` 调整为：

```text
服务ID + IP
```

同一 IP 在 ERP 的授权不能自动获得 RDP 或其他服务权限。用户撤销本人授权时，只有当相同“服务 + IP”不存在其他有效授权，才删除对应 frps 规则。

## 6. 实现前置条件

当前 frps 是全局白名单，因此“选择服务”只能作为界面信息，不能形成真正的服务隔离。正式启用服务选择前必须完成：

1. frps 白名单从全局规则扩展为按代理或服务维护规则。
2. frps 管理 API 增加稳定的 `serviceId` 或代理标识。
3. SQLite grant 表增加 `service_id`，并提供兼容迁移。
4. gateway 按 `(service_id, ip)` 聚合有效期并执行对账。
5. 卡片回调只接受后台服务目录中的服务代码。
6. 补充跨服务越权、共享 IP、撤销和到期恢复测试。

在这些条件完成前，机器人不得把全局授权描述成“仅授权某个服务”。

## 7. 验收标准

- 新员工只知道 `/start` 也能完成申请、查询和撤销。
- 卡片和文字回复不出现“加白”“删白”“TTL”等内部术语。
- 操作者身份始终取飞书可信回调，不取按钮 value 或消息正文。
- 用户不能查询或撤销其他用户的授权。
- 当前全局模式明确提示授权覆盖全部现有内网服务。
- 服务模式上线后，一个服务的授权不能访问其他服务。
- 重复点击撤销按钮不会造成重复变更或延长授权时间。
